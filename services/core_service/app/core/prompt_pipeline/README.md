# Prompt Pipeline (Модульная архитектура сборки промпта)

Пакет `app.core.prompt_pipeline` отвечает за многоэтапное формирование контекста и payload для языковых моделей (Gemini / Polza.ai) в `core_service`.

## Архитектура и стадии

Пайплайн построен по паттерну Chain of Responsibility / Strategy с общим контекстом `PipelineContext`.

```
[User Input]
     │
     ▼
IdentityStage       (Этап 1: Загрузка Chat, Character, UserPersona, Scenario)
     │
     ▼
LorebookStage       (Этап 2: Aho-Corasick стемминг + векторный семантический поиск + Core-атрибуты)
     │
     ▼
RAGStage            (Этап 3: Поиск по эпизодической памяти в дереве сообщений через CTE + pgvector)
     │
     ▼
ScenarioStage       (Этап 4: Оценка чекпоинтов сценария, директивы и детекция застревания сюжета)
     │
     ▼
HistoryStage        (Этап 5: Реконструкция последних 20 сообщений от текущего листа ветки)
     │
     ▼
AssemblerStage      (Этап 6: Генерация системного промпта, профилей, безопасности и OpenAI payload)
     │
     ▼
[Final Payload]
```

## Структура пакета

* `pipeline.py`: Главный фасад `PromptPipeline`, управляющий последовательным выполнением стадий и предоставляющий единый интерфейс вызова `build_payload(user_text)`.
* `context.py`: Датакласс `PipelineContext`, инкапсулирующий состояние, загруженные модели, коллекции фактов, воспоминаний и историю диалога.
* `stages/`:
  * `base.py`: Базовый абстрактный класс `PipelineStage`.
  * `identity_stage.py`: Загрузка связанных сущностей из БД одним запросом с `selectinload`.
  * `lorebook_stage.py`: Гибридный поиск записей лорбуков (стемминг корней слов через Aho-Corasick + pgvector) с проверкой флага `is_acquainted`.
  * `rag_stage.py`: Поиск эпизодов по косинусной дистанции среди предков сообщения в рекурсивном CTE дерева сообщений с временным затуханием (Hybrid Scoring).
  * `scenario_stage.py`: Проверка активных чекпоинтов сценария и инъекция директивы вмешательства `[CRITICAL NARRATIVE INTERVENTION]` при `messages_spent >= 8`.
  * `history_stage.py`: Обход дерева сообщений вверх по ветке с ограничением глубины 20 и форматированием блоков размышлений `<Internal_Analysis>`.
  * `assembler_stage.py`: Сборка финального текстового шаблона, локализация проверки реальности (`[Проверка реальности...]`), фильтры безопасности по возрасту пользователя и формирование словаря `payload`.
